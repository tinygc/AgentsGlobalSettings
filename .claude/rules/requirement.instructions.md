# 要件定義フェーズのルール

## 必須ドキュメント構成

`requirement/REQUIREMENTS.md` は以下のセクションを全て含めてください：

1. プロジェクト概要
2. 対象ユーザー
3. 機能要件（FR）
4. 非機能要件（NFR）
5. 制約事項
6. スコープ外
7. 用語集

## 機能要件（FR）の記述ルール

- 各 FR に `FR-001` 形式の一意のID を付与すること
- 各 FR に「入力・処理・出力」を明記すること
- 曖昧表現（「適切に」「なるべく」「等」）を使用しないこと
- テスト可能な条件（合否判定できる期待値）で記述すること

## 非機能要件（NFR）の記述ルール

- 各 NFR に `NFR-001` 形式のID を付与すること
- 定量値（「99.9%以上」「3秒以内」「最大1000件」など）を必ず含めること

## トレーサビリティ

- 要件変更時は、影響を受ける下流ドキュメント（アーキテクチャ・UI仕様・テスト仕様）を全て見直すこと
- 削除された FR は「スコープ外」セクションに記録すること

## フェーズ進行の条件

requirements-reviewer による以下のチェックが完了するまで次フェーズへ進まないこと：

- [ ] 全 FR に ID が付与されている
- [ ] 全 NFR に定量値が含まれている
- [ ] 曖昧表現が除去されている
- [ ] テスト可能性が確認されている
