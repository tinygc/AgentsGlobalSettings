# テスト設計フェーズのルール

## 前提条件

- `requirement/REQUIREMENTS.md` が存在し、requirements-reviewer の承認を得ていること

## テスト仕様書の必須構成

`test/TEST_SPEC.md` は以下のセクションを全て含めること：

1. テスト方針
2. テストスコープ
3. テストケース一覧
   - 機能テスト（FR 対応）
   - 非機能テスト（NFR 対応）
   - エラー系テスト
4. 要件トレーサビリティマトリクス（FR-xxx → TC-xxx）
5. 自動化計画

## テストケースの記述ルール

各テストケースは以下の項目を全て含めること：

| 項目 | 説明 |
|---|---|
| TC-ID | `TC-001` 形式の一意のID |
| 対応 FR | `FR-xxx` の ID |
| テスト名 | 何をテストするかの短い説明 |
| 前提条件 | テスト実行前の状態 |
| 操作手順 | テストの実施手順 |
| 期待結果 | 合否判定できる具体的な期待値 |
| 自動化 | 自動化可能 / 手動 |

## カバレッジ要件

- 全 FR に対して最低1つのテストケースを作成すること
- 各 FR につき正常系・異常系を両方含めること
- 境界値（最大値・最小値・境界±1）のテストを含めること

## トレーサビリティマトリクスの形式

```
| FR-ID  | FR 名称 | TC-ID(s) | カバー済み |
|--------|---------|----------|-----------|
| FR-001 | ...     | TC-001, TC-002 | ✅ |
```

## フェーズ進行の条件

test-reviewer による以下のチェックが完了するまで実装フェーズへ進まないこと：

- [ ] 全 FR にテストケースが対応付けられている
- [ ] トレーサビリティマトリクスが完成している
- [ ] 正常系・異常系・境界値が含まれている
- [ ] 自動化計画が策定されている
