# セッション振り返り（改善反映）

このスキルは、1 セッションの作業後に「うまく進められなかったこと」と「ユーザーからの指摘」を整理し、Sub Agent / Skills / Rules へ反映可能な改善案に変換します。

## 目的

- 失敗や手戻りを再発防止可能な形にする
- 口頭フィードバックを運用資産（agent/skill/rule）に変換する
- 次回セッションで同じミスを減らす

## 入力

- 当該セッションのやり取り
- ツール実行ログ（必要な範囲）
- ユーザーからの明示的指摘
- 変更したファイル一覧（任意）

## 出力

以下の形式で、簡潔に出力してください。

```md
## Session Retrospective

### 1. 事実サマリー
- 進行が止まった/遅延した事象:
- ユーザー指摘:

### 2. 原因分類
| ID | 事象 | 原因カテゴリ | 根拠 |
|---|---|---|---|
| R-001 | ... | 指示不足/手順不足/形式不一致/制約未考慮/検証不足 | ... |

### 3. 改善アクション
| A-ID | 対象 | 更新ファイル | 変更内容 | 優先度 |
|---|---|---|---|---|
| A-001 | Sub Agent | .claude/agents/implementer.agent.md | 出力フォーマット追記 | High |
| A-002 | Skill | .claude/skills/orchestrate-workflow/SKILL.md | 最終振り返り工程を必須化 | High |

### 4. 反映パッチ案（最小差分）
- A-001:
- A-002:

### 5. 次回の実行チェック
- [ ] 今回の改善が反映済み
- [ ] 同種の失敗が再発していない
```

## 判断ルール

1. 事実と推測を分離する（推測は「仮説」と明記）
2. ユーザー指摘は原文要旨を保持する
3. 改善先は最小スコープを選ぶ
4. 一度に大改修しない。まず再発率の高い項目から直す

## 反映先の選び方

- 同じ失敗が特定 Agent で繰り返す: `.claude/agents/*.agent.md`
- 手順抜けでフェーズ横断的に発生: `.claude/skills/*/SKILL.md`
- 品質基準の欠落が原因: `.claude/rules/*.instructions.md`
- 会話スタイルや全体運用の揺れ: `AGENTS.md`

## 実行手順

1. セッション終了前に失敗事象と指摘を列挙する
2. 原因分類テーブルを作る
3. 改善先と最小差分を決める
4. 必要なファイルを更新する
5. 更新内容と未対応項目をサマリーで返す

## 完了条件

- 改善事項がある場合は、最低 1 件以上の改善アクションが定義されている
- 改善事項がない場合は、その旨と判断根拠が記録されている
- 各アクションに更新対象ファイルが紐付いている
- 次回チェック項目が記録されている
