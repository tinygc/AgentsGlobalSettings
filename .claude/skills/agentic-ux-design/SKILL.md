# AIエージェント体験設計スキル

UIデザイン時にAIエージェントの体験設計を行うためのスキル。  
出典: [AIエージェント体験設計の基礎と実践の1年。やってわかった10のハマりどころ](https://note.com/art_reflection/n/n993d62dbe2f0)

---

## 使い方

AIエージェントを含むサービスのUI設計を行う際、以下のチェックリストと原則に従って設計を進める。  
`ui-designer` エージェントが本スキルを参照し、各画面・フローの設計時に適用する。

---

## エージェント設計の基本プロセス

### 1. スタートとゴールの設定
- ユーザーのどの状態をスタートとし、どのゴールにAIエージェントで辿り着くかを描く
- エージェントが担う範囲を明確にする

### 2. 理想のプロセスと振る舞いを書き出す
- 最も品質高くフローをこなす手順を定義する
- 進め方だけでなくAIの態度（プロらしく提案？確認型？）も設計する
- シナリオ/ストーリー形式でフロー化する

### 3. AIの作業と人間の介入の線引き
- AIの領分: 大量データ比較、照会、計算、ルーティン処理
- 人間の領分: 最終的な好み判断、予算確定、決済承認
- 不可逆な操作は必ず人間の承認を挟む

### 4. プロトタイピングと改善
- UIに落とし込む（チャット形式？ボタン提示？）
- 「どれぐらい細かく聞くか」「何を表示するか」「通知タイミング」を軸に改善

---

## 4つの設計原則

### 原則1: 信頼性 (Reliability)
- エージェントが「何ができて、何ができないか」の境界線を明確にする
- 一貫したパフォーマンスを提供し、心理的安全性を担保する

### 原則2: 透明性 (Transparency)
- 「なぜその行動をとったのか」の根拠を提示する
- ユーザーがAIの思考を自分の知覚の延長として捉えられるようにする

### 原則3: 制御性 (Controllability)
- ユーザーがいつでも主導権を握り、修正・停止できるようにする
- 重要な判断をAIに丸投げさせず、人間が最後のハンドルを握る手応えを残す

### 原則4: 復元性 (Resilience)
- AIが誤った際にやり直しができる仕組みを設ける
- 不可逆なタスクにしない。ユーザーと一緒に問題を特定・リカバリーする

## 10のハマりどころチェックリスト

### フェーズ1: 入力（合意形成）

#### 1. 期待値の提示
- [ ] エージェントが「何ができるか」を具体的に提示しているか
  - NG: 「旅行サポートAIです」
  - OK: 「旅行プランの提案、移動手段・宿・レストランの提案・予約をサポートします」
- [ ] タスクの境界線を事前にユーザーと握れているか
- [ ] できることの提示がユーザーの指示品質を向上させる設計になっているか

#### 2. 不完全な指示と合意形成
- [ ] **入力補助**: 選択肢、おすすめプロンプト、テンプレートを用意しているか
- [ ] **質問**: 曖昧な指示に対して適切な深掘り質問を行う設計があるか
- [ ] **合意形成**: 走り出す前に「私はあなたの指示をこう理解しました」と解釈を返すプロセスがあるか
- [ ] ユーザーの指示は常に不完全であることを前提に設計しているか

#### 2'. 対話を通じた欲求発見
- [ ] 一問一答の情報埋めではなく、思考を引き出す問いを挟むか検討したか
- [ ] ユーザーが対話を通じて自分の欲求に自覚的になるプロセスがあるか

#### 3. インジェクション対策
- [ ] **ユーザー起点**: 脱線に対してソフトなガードレール（本分を保ちつつ柔軟に対応）を設計しているか
- [ ] **データソース起点**: 外部データはあくまで「客観的事実」として扱い、ユーザー命令を最上位に置く階層構造を保っているか
- [ ] 不審な命令検知時にユーザーへ開示する仕組みがあるか

### フェーズ2: プロセス（並走）

#### 4. 理想のフローを設計する
- [ ] 人間が理想の答えを導く思考ステップを解明し、AIの振る舞いとして再現しているか
- [ ] 意図の解釈→データ収集→矛盾の検証→価値観に基づく選択の一連プロセスを定義しているか
- [ ] 「専門家ならどう進めるか」をフローに反映しているか

#### 5. 待ち時間の可視化
- [ ] プログレスバーだけでなく「今何をしているか」を表示しているか
- [ ] AIの思考の足跡（なぜ候補Aを除外したか等）を可視化しているか
- [ ] 画面を離れてよいかどうかを伝えているか（通知設計を含む）

#### 6. 確認と介入の設計
- [ ] タスク重要度に応じた3段階のレベル分けをしているか
  - **Critical**: 不可逆なアクション・金銭発生 → 人間による承認必須
  - **Warn**: AIの判断で進めてよいがズレるリスクあり → 事前説明・状況報告
  - **Info**: 軽微な判断 → ログに記録、後で確認可能
- [ ] Warn の閾値をユーザーに委ねる仕組み（「お任せモード」「慎重モード」等）を検討したか
- [ ] 選択の影響範囲（金銭的・時間的・物理的リスク）をユーザーに伝えているか
- [ ] AIエージェント特有の「コンテクストの欠落」を考慮した確認設計になっているか

### フェーズ3: 成果（信頼と成長）

#### 7. 選択の根拠を開示する
- [ ] 「なぜその判断・その形になったか」の意思決定履歴を適切な解像度で開示しているか
- [ ] 結論だけでなく、比較・葛藤の形跡を見せているか
- [ ] 成果物の利用シーン（画面の外）でも根拠にアクセスできるか

#### 8. 免責と承認の設計
- [ ] 不可逆な操作でAIは「実行者」ではなく「秘書」として振る舞う設計か
- [ ] 承認疲れを起こさない適切な説明と証跡を残す設計か
- [ ] AIの誤情報が第三者に損害を与えるリスクを考慮しているか
- [ ] ユーザーが「自分の責任で選んだ」と納得できる体験をデザインしているか

#### 9. 課金体系が行動を規定する
- [ ] 課金体系がユーザーの行動に負のインセンティブを与えていないか
  - 提案数課金 → ユーザーが冒険しなくなる
  - 従量課金（トークン課金） → ユーザーが妥協する
- [ ] 試行錯誤にコストがかからない設計を検討したか（定額制 / 成果報酬型）
- [ ] 課金設計がエージェントの自律性を楽しむ余裕を奪っていないか

#### 10. フィードバック・ループの設計
- [ ] **パーソナライズの深化**: ユーザー個別の好み・暗黙の了解を学習するプロセスがあるか
- [ ] **基盤としての成長**: 個別ユーザーのフィードバックがサービス全体の品質向上に還元される仕組みがあるか
- [ ] 一度きりのタスク完了でなく、長期的な関係性を築く設計になっているか

## 追加考慮事項

以下はまだ確立された知見が少ないが、設計時に考慮すべき事項：

- **エージェントのキャラクター/態度**: 秘書か相棒か、プロフェッショナルかフレンドリーか。ミス時の許容度や指示の出しやすさに影響
- **マルチモーダルな連続性**: PCで指示→スマホで進捗確認→タブレットで成果閲覧のようなデバイス横断体験
- **複数エージェント間の協調**: 一つのタスクに複数エージェントが関わる場合のUX
